# DinoBloom 细胞图像 DDPM 与条件生成研究计划

## 研究目标

先建立可复现的白细胞/血液细胞无条件图像生成基线，检查模型能否覆盖数据中的细胞外观与成像变化；再评估能否根据可验证的细胞类型或疾病标签生成具有相应形态特征的图像。生成结果用于研究与方法评估，不作为临床诊断依据。

## 可行性评估

路线总体可行，但应把“无条件生成学到细胞组成”改为更准确的目标：无条件扩散模型学习训练图像的像素分布，可能生成细胞、染色、背景和采集伪影的组合；它不会自动提供可解释的细胞部件表示，也不能保证学到的是疾病相关因素。需要用独立分类器、形态测量、专家复核及分布指标来验证生成图像。

DinoBloom 是以多个外周血及骨髓数据集训练的血液学图像表征模型/基础模型，并非一个单独的数据集。项目中应明确所用图像的原始数据集、染色/成像来源、标签定义、许可和患者信息，再决定是否采用仓库整理的 DinoBloom 相关数据。数据集现有分析材料和约 10K 子集目标可作为起点，但 10K 对先跑通 DDPM 与小规模可行性检查足够，不保证支持稀有疾病亚型的高质量生成。

从无条件图像生成到疾病可控生成是合理的渐进路线，但疾病形态和标签之间可能存在混杂：染色、显微镜、实验室、裁剪方式及患者差异都可能被模型当成疾病信号。疾病条件生成要求相对可靠且有足够样本的疾病标签，并需要按患者或玻片分组切分，避免近重复图像泄漏。若疾病标签只存在于患者级，不能未经论证就把它当作单细胞标签。

## 研究问题与假设

1. **无条件基线：**在固定数据和分辨率下，DDPM 是否能生成视觉上可信、与真实集分布接近且具备多样性的单细胞图像？
2. **数据规模与质量：**生成质量主要受数据规模、类别不平衡、图像预处理，还是模型/采样设置影响？每次实验只改变一个主要因素。
3. **条件控制：**对样本量充足、标签可信的细胞类别/疾病亚组，类别条件 DDPM 是否能控制目标类别，同时保留形态多样性？
4. **形态属性控制（探索项）：**对核质比、细胞面积、核分叶/圆度等可重复测量属性，连续条件是否能产生方向一致、且不牺牲图像真实性的变化？此项不预设这些属性可单独操控，也不把生成相关性解释为疾病因果机制。

## 分阶段实施

### 阶段 0：数据与研究范围确认

- 从仓库数据清单中确定一个主数据集/子集；记录来源、图像数、标签、患者/玻片标识、染色和采集域、许可及数据使用限制。
- 先做图像完整性、分辨率/通道、重复/近重复、标签一致性、类别计数和可视化抽查；保留原始数据只读，所有处理写入独立目录。
- 建立患者/玻片级训练、验证、测试划分；有患者 ID 时严禁把同一患者图像分到不同集合。对来源域差异单独记录。
- 定义生成目标是单细胞裁剪图还是视野图。若为单细胞裁剪图，统一尺寸与背景处理，保留细胞边缘信息，不做会改变形态的非等比缩放。
- 交付物：数据卡、子集清单、拆分清单、预处理配置、代表性网格图及类别分布报告。

### 阶段 1：端到端小规模 DDPM 验证

- 使用 CIFAR-10 复现继续作为代码/环境 sanity check；其结果不能作为医学图像生成效果证据。
- 在选定细胞子集上先跑固定随机种子的小规模 smoke run，确认数据读取、前向加噪、训练、保存/恢复、采样全链路正确。
- 初始基线可从 64×64 或 128×128 RGB 图像的 U-Net ε-prediction DDPM 起步；根据细胞关键结构和 GPU 资源决定最终分辨率。记录线性或 cosine β 日程、T、优化器、学习率、有效 batch size、EMA、训练步数及采样设置。
- 如果图像缩到 64×64 会抹掉核染色质/颗粒等关键形态，则改用 128×128 或更高分辨率，并先做资源测算。避免一开始同时比较多个架构。
- 交付物：首个可重复 checkpoint、训练曲线、样本网格、失败案例及资源记录。

### 阶段 2：无条件基线与真实性评估

- 在冻结的训练/验证/测试划分上训练正式基线；不通过查看测试样本来选模型或调参。
- 保存配置、代码版本、依赖版本、种子、硬件、日志、checkpoint 和采样命令；每次正式实验使用唯一实验 ID。
- 定量评估：在一致预处理下报告 FID/KID（使用合适的细胞/医学图像特征提取器并说明特征空间）、precision/recall 或覆盖度、重复率/最近邻相似度；同时评估生成图与训练图的近邻，排查记忆化。
- 形态评估：用独立分类器测类别分布，用细胞/细胞核分割或图像分析提取面积、圆度、核质比等指标；报告与真实测试集的分布差异。若没有可靠工具，明确这些指标的限制，并安排盲法专家抽样审阅。
- 视觉审查关注结构完整性、核/胞质边界、染色和背景伪影、细胞外形多样性。FID/KID 或好看的样图单独都不足以证明医学真实性。
- 设定进入下一阶段的门槛：样本基本可辨认、没有明显模式坍塌/严重记忆化，且评估流程可稳定复现。门槛应在正式比较前预先写入实验记录。

### 阶段 3：条件生成最小可行实验

- 先用可靠的细胞类型标签做 class-conditional DDPM（类别嵌入注入 U-Net；可对比 classifier-free guidance）。这能检验条件接口，通常比一开始做疾病亚型更有数据支撑。
- 若疾病标签达到预先设定的样本量和标注质量要求，再选择一个疾病/对照对照任务；明确标签层级是单细胞还是患者/玻片级，并仅用真实标签监督对应层级。
- 使用患者/玻片分组划分。训练集用于拟合，验证集用于选择 guidance 和 checkpoint，测试集只用于最终一次报告。报告各组样本数及不平衡处理，避免将重复增强图像当作独立样本。
- 评估条件遵循度（独立分类器/专家判断）、图像真实性、多样性、类间可分性、近邻记忆化和跨来源泛化。对 guidance 强度作小范围消融，防止强引导制造不自然的“类别特征”。
- 若目标只是控制细胞形态而非疾病诊断，可优先试连续形态属性条件；属性必须由可靠分割/人工标注得到，并做条件值与生成形态的单调性/校准分析。

### 阶段 4：稳健性、局限与研究结论

- 在独立数据来源/染色域上检验分布偏移；如果没有可用外部数据，将结论限定为当前来源域。
- 做按来源、患者、类别的分层误差分析，检查模型是否用背景、染色或设备线索代替目标形态。
- 报告失败类别、罕见类不确定性、患者泄漏检查、隐私/记忆化检查、数据许可及生成图用途限制。
- 只有当无条件基线稳定且条件评估可信后，再比较 DDIM/LDM/DiT 等模型；否则先修正数据与评估设计。

## 建议的最小实验矩阵

| ID | 实验 | 主要变量 | 目的 |
|---|---|---|---|
| DB-00 | 数据审计与划分 | 数据来源/预处理固定 | 确认规模、标签、泄漏风险和形态保真度 |
| DB-01 | 小规模 smoke run | 少量步数 | 检查训练采样全链路 |
| DB-02 | 无条件 DDPM 基线 | 固定数据与模型配置 | 建立真实性、多样性和记忆化基准 |
| DB-03 | 关键设置消融 | 每次仅改一项（分辨率、数据量或 schedule） | 找到质量/成本的主要影响因素 |
| DB-04 | 细胞类别条件生成 | 类别条件/引导强度 | 验证可控生成是否成立 |
| DB-05 | 疾病条件试验 | 有足量可靠疾病标签时才执行 | 检验疾病标签控制及跨患者泛化 |
| DB-06 | 形态属性条件（可选） | 单一连续形态属性 | 检查形态方向控制及真实性权衡 |

## 风险与应对

- **DinoBloom 名称混淆：**区分 DinoBloom 基础模型与组成它/被项目整理的公开数据集；逐个记录实际图像来源。
- **数据量或稀有类不足：**先报告类数和患者数；减少疾病目标范围，必要时以类别条件作为方法学阶段，不夸大罕见疾病生成能力。
- **域混杂：**按来源/染色审计并分组切分；报告跨域测试，谨慎解释疾病相关形态。
- **标签层级错误：**患者级诊断不能自动转成每个细胞的细粒度疾病标签；以患者为单位构造标签或调整研究问题。
- **评估指标不适配：**自然图像预训练特征下的 FID 可能不充分；搭配细胞领域特征、形态统计、专家盲评和记忆化检查。
- **资源受限：**优先使用已有 DDPM 代码和小分辨率验证；正式训练前估算存储、GPU 显存与训练时间，不在数据/环境未确认时启动大规模作业。

## 每个实验必须记录

沿用 `experiments/experiment_template.md`：研究问题、假设、数据版本与拆分哈希、预处理、模型/超参数、随机种子、软硬件、命令、日志和产物、定量与定性结果、失败分析、结论和下一步。原始数据不改写，结果与 checkpoint 不纳入 Git。
